## ৬.২ সিদ্ধান্ত যা আপনাকে নিতে হবে

1. **Staging কোথায়?** (ক) দ্বিতীয় Supabase Free প্রজেক্ট `xzm-team-staging` + আলাদা Netlify/Cloudflare প্রিভিউ — *আমার সুপারিশ*; (খ) শুধু CI-র থ্রোঅওয়ে Postgres (বিদ্যমান) — দ্রুত কিন্তু UI/Auth/Storage পরীক্ষা হয় না; (গ) Supabase Pro-তে Branching।
2. **GitHub `production` Environment + আপনি Required reviewer** চালু করব কি? (এটা না হলে "Production-এ Approval" DB-তে রেকর্ড হবে কিন্তু ডিপ্লয় আটকাবে না।)
3. **ব্যাকআপ:** (ক) Pro-তে উন্নীত (দৈনিক ব্যাকআপ, PITR অ্যাড-অন), (খ) GitHub Action দিয়ে নির্ধারিত `pg_dump` (একটি read-only DB-ইউজার ও এনক্রিপ্টেড স্টোরেজ সিক্রেট লাগবে)। কোনটি?
4. **অডিট কভারেজ (M7):** কোন টেবিলগুলোতে trigger বসবে — আমার সংবেদনশীল তালিকা (`04` M7) অনুমোদন করবেন, নাকি বাড়ান/কমান?
5. **পুরনো সিস্টেম-মেনু** (ইউজার ও রোল, অ্যাডভান্সড রোল, ব্র্যান্ডিং ইত্যাদি) আপাতত যেখানে আছে সেখানেই থাকবে, নতুন গ্রুপে শুধু লিঙ্ক — ঠিক আছে?
6. **Retention:** `sc_error_events`/`sc_health_snapshots` ৯০ দিনের বেশি পুরনো সারি সংকুচিত/মোছা চলবে কি? (এগুলো ব্যবসার ডাটা নয়; `audit_logs` কখনোই নয়।)
7. **Phase 1 শুরুর অনুমোদন:** Phase 0 শেষে Phase 1 Staging-এ শুরু করব — হ্যাঁ/না।

## ৬.৩ সুপারিশকৃত পরের ধাপ

Phase 0 অনুমোদন দিন (সিদ্ধান্ত ১, ২, ৩ সহ)। আমি তখন শুধু শুরু করব: ড্রিফট সোর্স রিপোতে আনা, ডকুমেন্টের "ই-আর-পি" শিরোনাম ঠিক, ও Registry-র `scan.mjs` — যেগুলোর কোনোটাই লাইভ ডাটাবেস বা লাইভ সাইট বদলায় না।
