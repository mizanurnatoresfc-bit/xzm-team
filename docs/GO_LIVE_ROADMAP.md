# XZM TEAM — পুরো সাইটের অডিট, তিন রোলের ডেমো ও লাইভ রোডম্যাপ

তারিখ: ২২ নভেম্বর ২০২৬ · যে কোড দেখা হয়েছে: `main` (commit `7ecca09`) + এই ব্রাঞ্চের ঠিক করা অংশ। পরীক্ষার সংখ্যাগুলো `main`-এর পরের দুটো বদল (জোনাল স্ট্যাটাস, জেলার কভারেজ ম্যাপ) মেলানোর পরের; পাতা ধরে হাঁটা হয়েছিল তার আগের কোডে।

পুরোনো `PRODUCTION_ROADMAP.md` (১৩ নভেম্বর) এখন আর সত্যি অবস্থা বলে না — এই ফাইলটাই চলতি রোডম্যাপ।

## ২. অডিট কীভাবে হলো

১. **ডাটাবেস:** একটা আলাদা, ফেলে দেওয়ার মতো PostgreSQL 16 ডাটাবেসে সব migration বসিয়ে পুরো SQL পরীক্ষা চালানো।
২. **রোল ডেমো:** সেই ডাটাবেসে একটা জোন, তিনটা হাব, একজন জোনাল ম্যানেজার, একজন হাব ম্যানেজার, একজন রাইডার
   (লগইনসহ) ও আরও কয়েকজন কর্মী বসানো। তারপর আসল ব্রাউজারে সাইট খুলে প্রতিটা রোল হিসেবে ঢোকা — সাইটের প্রতিটা
   ডাটাবেস অনুরোধের উত্তর ওই ডাটাবেস থেকে, সেই মানুষের পরিচয়ে, আসল RLS নিয়ম দিয়ে দেওয়া হয়েছে।
   টুলটা রিপোতে রাখা আছে: `scripts/role-demo/` (যেকোনো সময় আবার চালানো যায়)।
৩. **লাইভ:** Supabase থেকে শুধু পড়া — সংখ্যা, migration তালিকা, নিরাপত্তা পরামর্শ। লাইভে কিছু লেখা বা বদলানো হয়নি।

**যা এই অডিটে পরীক্ষা হয়নি (সীমা):**
- আসল লগইন (পাসওয়ার্ড, ৫ বার ভুলে লক), পাসওয়ার্ড রিসেটের ইমেইল, Edge Function (`auth-login`, `admin-users`, `nodi-ai`, `push-send`) — এগুলো শুধু লাইভ Supabase-এ চলে।
- ফাইল/ছবি আপলোড ও দেখা (Storage), ফোনের push, লাইভ ঘণ্টা (realtime), Android APK।
- সুপার অ্যাডমিন, HR, হিসাব বিভাগের রোলে পাতা ধরে ধরে হাঁটা (এগুলো smoke test ও SQL পরীক্ষায় আছে, কিন্তু এই ডেমোতে তিন রোলই ধরা হয়েছে)।
এগুলো রোডম্যাপের ধাপ ২-এ লাইভে হাতে পরীক্ষা করার তালিকায় আছে।
