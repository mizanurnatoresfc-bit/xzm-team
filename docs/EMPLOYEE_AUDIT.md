# কর্মী ব্যবস্থাপনা — অডিট রিপোর্ট (২১ নভেম্বর ২০২৬)

পাতা: `/app/hr/employees` (`web/src/pages/hr/Employees.tsx`, তালিকা `web/src/components/DataTable.tsx`)।
নতুন কোনো আলাদা মডিউল বানানো হয়নি — বিদ্যমান পাতাই ঠিক করা হয়েছে। লাইভ ডাটাবেসে কিছু লেখা বা বদলানো হয়নি (শুধু পড়া)।

## ১. ১৪৫ বনাম ২ — আসল কারণ

| যাচাই | ফল |
|---|---|
| ডাটাবেস | `employees`-এ লাইভ রেকর্ড ১৪৫ (সক্রিয় ১৪৪, আইডির অপেক্ষায় ১)। সবার জোন ও হাব আছে, হাবের জোনের সাথে মেলে, কেউ বন্ধ হাবে নেই। |
| API | পাতা একবারে `employees?archived_at=is.null&limit=2000` আনে। সুপার অ্যাডমিনের সেশনে RLS চালিয়ে একই কোয়েরি **১৪৫** ফেরত দেয়। |
| RLS | `employees_read` = `hr.employee.view` (জোন/হাব অনুযায়ী) অথবা নিজের রেকর্ড। প্রতিটি অ্যাকাউন্ট হিসেবে গুনে দেখা: সুপার অ্যাডমিন ১৪৫, দুই জোনাল ম্যানেজার ১৩৩ ও ১২, হাব ম্যানেজার ১১–৩২, বাকিরা শুধু নিজেকে (১)। **কেউই ঠিক ২ জন দেখেন না** — তাই ডাটাবেস বা RLS দোষী নয়। |
| UI | তালিকার (DataTable) নিজের একটা লুকানো "ফিল্টার" আছে, যা এই ডিভাইসে (`localStorage` → `xzm_dataview.employees`) মনে থাকে। পাতার নিজের ফিল্টার (পদ, হাব, অবস্থা) থেকে এটা আলাদা। |

**কারণ:** পাতায় দুই সেট ফিল্টার ছিল। তালিকার নিজের ফিল্টারে একবার কিছু বাছলে (যেমন পদবি = Hub CC বা Zonal Manager, দুটোতেই ঠিক ২ জন) সেটা রিলোডের পরেও থেকে যেত। উপরের কার্ড তখনও "মোট কর্মী ১৪৫" দেখাত, আর পাতার "সব ফিল্টার মুছুন" বোতাম ওই ফিল্টারের কথা জানতই না। ফলে স্ক্রিনে থাকত মাত্র ২ জন।

স্মোক টেস্টে এটা হুবহু ঘটানো গেছে: মনে রাখা একটা হাব ফিল্টারে পুরোনো কোড ১২ জনের জায়গায় **২ জন** দেখায়, নতুন কোড ১২ জনই দেখায়।

## ২. যা যাচাই করা হলো

| বিষয় | অবস্থা |
|---|---|
| Search | ঠিক আছে — নাম (বাংলা/ইংরেজি), আইডি, মোবাইল, বাংলা অঙ্ক (`১০০৭`) দিয়ে খোঁজা যায়। |
| Filter | **P0 ঠিক করা হয়েছে** (উপরে)। এখন শুধু পাতার নিজের ফিল্টার আছে, আর "সব ফিল্টার মুছুন" সব মোছে। |
| Pagination | ব্রাউজারেই হয়, প্রতি পাতায় ২৫/৫০/১০০। ১৪৫ জনের জন্য ঠিক আছে। **P2:** `limit 2000` — কর্মী ২০০০ পেরোলে বাকিরা কিছু না বলেই বাদ পড়বে (Supabase-এর `max_rows` সাধারণত ১০০০, তখন আগেই)। তখন সার্ভারে পেজিং লাগবে। |
| Loading | **ঠিক করা হয়েছে** — লোড হওয়ার আগে বা ভুল হলে কার্ডে "০" না দেখিয়ে "—"। |
| Error | **ঠিক করা হয়েছে** — ভুল হলে বার্তার পাশে "আবার চেষ্টা করুন"। |
| Empty | **ঠিক করা হয়েছে** — ফিল্টারে কেউ না মিললে "সব ফিল্টার মুছুন" বোতাম; একেবারে কেউ না থাকলে আলাদা লেখা। |
| শিরোনাম | এখন "১৪৫ জনের মধ্যে ১৪৪ জন দেখানো হচ্ছে" — স্ক্রিনে যতজন, ঠিক ততজন। "মোট কর্মী" কার্ডের নিচে লেখা "আপনি যে এলাকা দেখতে পারেন" (হাব ম্যানেজার নিজের হাবই দেখেন, সব রেকর্ড নয়)। |
| Responsive | PC ও ফোন সাইজে স্মোক টেস্ট পাস, পাশে স্ক্রল হয় না। |
| Bulk action | বদলি / সক্রিয়-নিষ্ক্রিয় / ভুল এন্ট্রি মোছা — অনুমতি (`hr.employee.edit`, `hr.transfer.edit`, `hr.employee.archive`) দেখে বোতাম আসে; ডাটাবেসও যাচাই করে। টেস্ট পাস। |

## ৩. খোলা বিষয় — মালিকের সিদ্ধান্ত লাগবে (এই PR-এ বদলানো হয়নি)

1. **P1 — Export/Print অনুমতি:** ডাটাবেসে `hr.employee.export` অনুমতি আছে, কিন্তু কর্মী তালিকার Excel / PDF / প্রিন্ট / "আইডি তৈরির ফাইল" / "ফরম্যাটে এক্সপোর্ট" এটা দেখে না। যিনি তালিকা দেখতে পারেন তিনিই নামাতে পারেন (RLS-এর কারণে শুধু নিজের এলাকার)। এখন যাঁদের কাছে এই অনুমতি **নেই**: Hub Manager (১০ জন), Zonal Manager (২), Staff (৩৩), Accounts Manager (১), Driver (১)। চালু করলে এঁরা আর এক্সপোর্ট করতে পারবেন না, যদি না রোলে অনুমতিটা দেওয়া হয়। তাই আগে আপনার সিদ্ধান্ত দরকার।
2. **P1 — এক্সপোর্ট আর স্ক্রিন মেলে না:** "ফরম্যাটে এক্সপোর্ট" ও "আইডি তৈরির ফাইল" এরিয়া/হাব/অবস্থা/খোঁজা মানে, কিন্তু **পদ** চিপ মানে না। পদ বাছলেও ফাইলে সব পদের লোক আসে। ঠিক করতে ডাটাবেস ফাংশনে নতুন প্যারামিটার লাগবে।
3. **P2 — "Staff" রোলে `hr.employee.view` আছে** (৩৩ জন)। রোলের স্কোপ অনুযায়ী এঁরা সহকর্মীদের তালিকা দেখতে পারেন। ইচ্ছাকৃত কিনা মিলিয়ে নিন।

## ৪. Rollback

শুধু ওয়েব কোড বদলেছে; কোনো migration বা ডাটা বদল নেই। ফেরত নিতে main-এ এই PR-এর merge commit `git revert` করে push করুন; সাইট আগের মতো হয়ে যাবে। কোনো ব্যবহারকারীর মনে রাখা সেটিং মোছা হয় না — পুরোনো ফিল্টারটা শুধু উপেক্ষা করা হয়।
